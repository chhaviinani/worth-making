# Stakeholder story

Inspired by Tony Fadell's *Build* (look around; same why). Encode the method, not the book. Do not quote the book.

## Goal

One product, several rooms, **no lies**. If the exec version needs a feature the user version forbids, you do not have a product yet.

Look around: other functions see different roadblocks. Assimilate that. Do not invent a new why per audience.

## Before you start

1. Read `templates/stakeholder-story.md` and `templates/story-card.md`.
2. Read `ideas/<slug>.md` and story file if they exist.
3. Ask who the rooms are. Do not invent politics.

## Interview

1. **User**: Why they care, buy, use, stick.
2. **Exec**: Outcome, risk, ask. No feature list.
3. **Maker / engineer**: The job, the handcuffs, what is out.
4. **Other functions**: Sales, support, marketing, ops: what they need to be true.
5. **Conflicts**: Fix the product, not the wording.

## Save

Write `ideas/<slug>-stakeholders.md`. Update `ideas/<slug>-story.md` if it exists.

Offer `board-one-pager` or `ceo-translation` when the room is the board or CEO.
