# Prototype before powerpoint

Inspired by Tony Fadell's *Build* (make the intangible tangible). Encode the method, not the book. Do not quote the book.

## Goal

A **journey someone can walk** this timebox, not a prototype of the object only, and not a pitch. Prototype discovery, first use, stuck, and success as far as you can. If a step is missing, they will trip.

## Before you start

1. Read `templates/prototype.md`.
2. Read story + Gen 1 if they exist. If no story, extract four lines or run `product-story`.
3. Ask. Do not invent a stack.

## Interview

1. **What must become tangible**: Why they care, buy, use, stick. Pick the gap.
2. **Who walks it**: Named person, how many, by when.
3. **Fidelity**: Paper, click-through, concierge (you are the backend), physical mock, live ugly.
4. **Steps in the journey**: Discover → start → succeed → fail. Which are fake vs real this week.
5. **Success / fail**: Observable. "They liked the slides" is not a result.
6. **Will not build**: Auth, admin, production ML, polish.

## Cut

Reject: a deck to "get buy-in" when five people could walk a fake journey this week. Sit stakeholders in the prototype.

## Save

Write `ideas/<slug>-prototype.md`.

Offer `customer-journey` if the path around the product is unmapped, `design-the-feeling` to script beats, or `data-versus-opinion` if the remaining question is actually data-driven.
