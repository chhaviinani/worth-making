# Design the feeling

Inspired by Tony Fadell's *Build* (story + whole journey, not the object). Encode the method, not the book. Do not quote the book.

## Goal

Specify **moments a named person feels**. Heart and mind. The product is the journey: how they find it, start, fail, and stay. Not a list of screens.

## Before you start

1. Read `templates/first-experience.md`.
2. Read `ideas/<slug>.md` and `ideas/<slug>-v0.md` if they exist.
3. Need a named person and a why. Extract four lines or run `product-story`.
4. Ask. Do not invent copy they did not choose.

## Interview

Ask in batches of 2–3.

1. **Person + moment**: Where they are in life, what they want in the next few minutes.
2. **Why should I care / buy / use / stick**: If these are not felt in the journey, the design failed.
3. **Discover**: How they first meet the story (the promise they hear, not an ad plan).
4. **First minutes**: Open → see → do. If they only read, the object is a brochure.
5. **Empty / first use**: No history. Are they lost?
6. **Stuck**: Error, delay, return. What happens without blame.
7. **Success**: They did the thing the why promised. How they know.
8. **Must feel true**: 1–3 beats; if missing, this is someone else's product.

## Cut

Reject: tours before the action, permission prompts before the promise, celebrating a click that is not the why.

Generation 1 should complete the core promise. Account walls only if identity *is* the product.

## Save

Write `ideas/<slug>-first-experience.md`. Update Gen 1 first-experience if that file exists.

End with: "After the first use they have ____." Next: `customer-journey` if touchpoints outside the first session are still blank; `version-zero` if scope crept; `prototype-before-powerpoint` to make it tangible.
